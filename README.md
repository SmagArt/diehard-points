# Калькулятор баллов Die Hard

Считает баллы зачёта за воскресную длительную: дистанция + средний темп + твой
коэффициент. Один файл `index.html`, без зависимостей и без интернета —
открывается двойным кликом и работает офлайн.

**Живая версия:** https://smagart.github.io/diehard-points/
_(подставится после включения GitHub Pages)_

## Что внутри

- ползунки дистанции (20–42.2 км), темпа (3:00–8:00/км) и коэффициента (1.0–2.0);
- галочка предварительной записи (+3 балла);
- блок «что выгоднее добавить» — километр против десяти секунд темпа;
- полная таблица баллов с подсветкой текущей ячейки;
- прогноз коэффициента при разной посещаемости.

## Правила, по которым считает

| Правило | Значение |
|---|---|
| Минимальная зачётная пробежка | 20 км и быстрее 7:00/км |
| Минимум баллов за зачётную | 5 |
| Медленнее 8:00/км | не учитывается вообще |
| Короче 20 км | считается пропуском |
| Успешная длительная | коэффициент +0.1 |
| Пропуск | коэффициент −0.2 |
| Диапазон коэффициента | 1.0 … 2.0 |
| Предварительная запись до воскресенья | +3 балла |
| Женский коэффициент | +10% к итогу |

Исходная таблица организаторов опубликована для коэффициента 2.0 — то есть это
потолок. Отсюда база = `таблица / 2`, а итог:

```
(база + 3 за раннюю запись) × коэффициент × 1.1 (женский зачёт)
```

Бонус за запись входит в базу **до** умножения, поэтому при высоком
коэффициенте он стоит заметно дороже трёх баллов.

**Сверено с фактическими начислениями (12.08.2026):**

| Ввод | Расчёт | Округлённо | Факт |
|---|---|---|---|
| 25.9 км @ 4:43, коэф 1.9, запись | 58.83 | 59 | 59 |
| 31 км @ 5:10, коэф 1.6, запись, ж | 55.97 | 56 | 56 |
| 26.19 км @ 5:39, коэф 1.1, запись | 21.43 | 21 | 21 |

**Насыщение таблицы подтверждено** по чужому профилю с шестью забегами 23–57 км:
52 км @ 4:20 → 64 балла и 57 км @ 4:24 → 62 дают один и тот же выведенный
коэффициент (1.293 и 1.295). Значит строка 42 км — потолок, и всё, что длиннее,
считается как 42. Если бы таблица продолжала расти, у 57 км коэффициент вышел бы
заметно ниже.

Там же четвёртое подтверждение порядка операций: 42 км @ 6:48 → 11 баллов.
Вариант `(база + 3) × k` даёт k = 1.02 и ложится в ряд посещений,
вариант `база × k + 3` даёт k = 1.41 и ряд ломает.

**Участок 35–42 км и коэффициент 2.0 тоже подтверждены** — по профилю участницы со
115 тренировками и серией без пропусков:

| Ввод | Расчёт | Факт |
|---|---|---|
| 67 км @ 5:12, коэф 2, запись, ж | 76.1 | 77 |
| 42 км @ 4:40, коэф 2, запись, ж | 94.5 | 94 |
| 21 км @ 4:14, коэф 2, запись, ж | 65.4 | 66 |

Коэффициент проверен на значениях 1.1, 1.29, 1.38, 1.6, 1.9 и 2.0 — множитель
линейный, отдельно проверять 1.0 смысла нет.

**Известная аномалия:** у той же участницы два забега ровно по 20 км дают заметно
меньше расчётного (42 против 52 и 44 против 48). Похоже, недобор целевой дистанции
города срезает баллы, но это гипотеза. На дистанциях от 21 км расхождений нет.

**Важно при вводе:** зачёт округляет дистанцию до целых километров и считает темп по
общему времени, включая остановки. Вводите те цифры, которые показывает сайт, а не
часы — они могут расходиться на несколько секунд на километр.

## Как обновить

Правишь `index.html`, коммитишь, пушишь — Pages пересобирает страницу сам.
Данные таблицы лежат в константе `TABLE` внутри `<script>`, темпы — в `PACES`.

## Включить GitHub Pages

Settings → Pages → Source: `Deploy from a branch` → Branch: `main`, папка `/ (root)` → Save.
Через минуту страница поднимется по адресу выше.
